# 15 — Native node modules (no EVM)

**In plain words:** the contracts that used to run on Ethereum now run as plain Python code
inside every TCL node. Each node checks the zero-knowledge proofs itself, punishes validators
that sign two different blocks, rotates validators on a schedule, and runs the notes and
governance rules. Everything uses only the Python standard library and works offline.

Code lives in `src/tcl/node/`; it is wired into the localnet in `src/tcl/localnet/node.py`.

| Piece | File | What it does |
|---|---|---|
| BN254 pairing | `bn254.py` | Elliptic-curve math and the optimal-ate pairing, written from scratch |
| Groth16 verifier | `groth16.py` | Checks snarkjs proofs against a `verification_key.json` |
| Notes | `notes.py` | Port of `NoteController.sol` (LIVE/DORMANT, eras, nullifiers, rearm, mint credit) |
| Governance | `governance.py` | Bounded parameter registry, conviction voting, timelock |
| Demurrage | `demurrage.py` | Same fixed-point rule as `tcl.ledger.demurrage_fixed`, with a governed rate |
| Chain glue | `chain.py` | Validator enrolment, evidence slashing, epochs, tx routing, state roots |

## 1. Double-sign evidence → slash + permanent ban

1. Every honest validator records the first vote it sees from each validator for each
   (kind, height, round), and relays it once on an evidence-gossip channel. That channel is
   never fed to the consensus engine, so it can't change how votes are counted.
2. If a validator sees a second, different signed vote for the same slot, it builds
   `DuplicateVoteEvidence`, checks both signatures, puts it in its pool and gossips it.
   Peers check it again before they accept it (fail-closed).
3. The next block carries the evidence as an unsigned `consensus/evidence` tx. The evidence
   proves itself with the two signatures. It is checked when the tx runs, and the penalty is
   applied **at block end**: the bond goes to `slashed_pool`, the seat is removed, and the
   person's nullifier is banned for good. Replays get `NULLIFIER_SPENT`, and forged
   evidence gets `BAD_PROOF`.

## 2. Epochs, rotation, enrolment and the randomness beacon

* **Beacon (ECVRF, RFC 9381 ECVRF-EDWARDS25519-SHA512-TAI, `consensus/vrf.py`):** each epoch,
  a leader is drawn from the previous seed. The leader publishes
  $\pi = \mathrm{VRF.prove}(sk, \texttt{"tcl-beacon"} \| \text{chain} \| e \| s_{e})$ in an
  unsigned `consensus/beacon` tx. Every node verifies $\pi$ against the leader's key. At the
  boundary the new seed is $s_{e+1} = \mathrm{SHA256}(s_e \,\|\, (e{+}1) \,\|\, \beta)$.
  The VRF code passes the three official RFC 9381 test vectors (B.3).
* **Why a VRF instead of commit-reveal:** a VRF has exactly one valid output for each key and
  input, so neither the leader nor any block proposer can try out different seeds. It finishes
  in one step and needs no per-epoch commit and reveal from every validator. Commit-reveal
  gives the last person to reveal the same one-bit "reveal or withhold" choice. It also needs
  everyone to take part, and an offline validator stalls it or forces penalties.
* **Remaining bias:** the leader can withhold its reveal. The seed then falls back to the fixed
  value $\mathrm{SHA256}(s_e \| (e{+}1) \| \texttt{"missed"})$, and the leader loses 10% of its
  bond plus its seat. That leaves at most one bit of choice, and using it costs money.
  A proposer could censor the reveal tx, but that only works if every proposer in the epoch
  does it. This replaces the old seed taken from commit signatures, which the proposer could
  steer.
* At the end of every height $h$ with $h \bmod \texttt{epoch\_blocks} = 0$, terms that have run
  out move into cooldown and seats are refilled by a seeded draw without replacement. If there
  aren't enough eligible people, the liveness override re-seats people whose terms just ended
  (this is logged).
* **Enrolment** (`consensus/enroll`, signed): requires mock personhood tier ≥ 2 and exactly the
  flat bond, which is moved into escrow. Each person can hold one entry.

## 3. In-node Groth16 (BN254)

* Anonymous `spend_nullifier` txs carry a snarkjs proof over the state-transition public
  signals. The nullifier must equal `anon_nullifier(public)`, which ties it to the proven
  statement.
* Note deposits are checked against `[id, denom, era, context, recipient, nullifier]`. Old-era,
  wrong-context and redirected-recipient proofs are all rejected (tested with the repo
  fixtures).
* `{"dev": true}` proofs are refused unless genesis sets `dev_proofs=true` (off by default).
* **Caveats:** pure Python and **not constant-time**. That's acceptable here because every input
  is public. One check takes about 0.4 s in CPython. Each node caches its own results.
  Verification keys are bundled in `src/tcl/node/vk/`, and a test makes sure they match their
  sources.

## 4. Notes (mint policy of PR #20, docs/11 §7.2)

* **Credit** = $\min(\text{claimed}, \mathrm{cap}_d, 40\%\,V, 3\ \text{TCL})$.
* **Reward** = $0.2\%\,V$, plus 0.25 TCL on the first mint of 5, 10 and 20 notes.
* **Ceiling:** credit plus reward is at most $60\%\,V$.
* **Re-arm:** no cost credit. The reward is paid only if the era lasted at least 7 days.
* **Small-note reserve:** 50% of each epoch's budget is kept for small notes.
* **Fallback:** a straight 1:1 swap. If no policy can be read, minting fails closed to 1:1.

Every number comes from the native registry within hard bounds matching `NoteController`: cost
cap ≤ 50%, fixed cap ≤ 10 TCL, bonus ≤ 1 TCL, reserve ≤ 80%, era age 1 to 90 days, reward ≤ 1%.
The per-denomination table test is a direct port of the Foundry
`test_DefaultScheduleAllDenominations`. Conservation is checked over a randomized walk.

## 5. Governance and demurrage

Each parameter has hard bounds set at genesis. The only way to change one is a proposal that
passes, waits out the timelock and then executes. Voting is one person, one vote, using the
mock personhood registry. Conviction follows
$Y(t+\Delta t) = 2^{-\Delta t/h}\,Y(t) + (1 - 2^{-\Delta t/h})\,S$ with $h$ = 7 days by default
(allowed range 3 to 30 days). A proposal needs a 10% quorum and a simple majority, or more than
66% for constitutional changes. Demurrage at the default rate is bit-identical to the ledger rule.
`DEMURRAGE_RATE_PPM_DAY` (100 to 1000) and `DEMURRAGE_THRESHOLD_TCL` (1M to 50M) are
governed. A passed change is copied into `demurrage_active` at the next epoch boundary, never
in the middle of an epoch, and every validator's ledger uses it from then on. Lazy settlement
applies the rule in force when an account is settled to that account's whole elapsed interval.

## 6. Multi-process localnet (real localhost TCP p2p)

`tcl localnet start --processes -n 4` runs each validator as its own OS process
(`tcl.localnet.proc`), with its own database and block log. The default in-process mode is
unchanged.

* **Transport** (`localnet/p2p.py`): length-prefixed canonical JSON. Both sides prove
  ownership of their Ed25519 node keys with fresh nonces, and only genesis validator keys are
  accepted. After the handshake every frame is signed and numbered, so tampered, replayed or
  reordered frames are rejected.
* **No encryption:** traffic is authenticated but readable on loopback. A real network needs
  a Noise-style key exchange plus encryption.
* **Offline:** the node process refuses any non-loopback connection.
* **Sync:** nodes exchange their heights. A node that is behind receives committed blocks,
  checks each certificate against its own validator set, and re-executes them. Tested with
  4 processes: one is killed with SIGKILL, the other 3 keep finalizing, and the restarted node
  catches up and agrees on the head hash and state root.

## What is NOT done yet (honest gaps)

* Personhood is a **mock**: tiers are trusted, and no ZK membership proof is checked.
* P2P is localhost-only with no encryption and a fixed peer list (genesis validators).
  Validators enrolled through a tx don't run a process yet.
* The VRF and Ed25519 code isn't constant-time. That's fine for a dev network, but it has to be
  replaced before keys hold real value.
* A validator that missed its beacon reveal can't top its bond back up yet, so it stays
  ineligible.
* Validators enrolled through the tx have no running node in the localnet yet. Only genesis
  nodes run engines.
* The trusted setup behind the bundled verification keys is dev-only.
